# 04. 과목 개발 가이드

> 새 과목을 만들 때 공통으로 지킬 규칙과 순서. 과목별 내용은 `subjects/<id>.md`, 껍데기 규약은 `03_껍데기_명세.md` 4장.

## 1. 진행 순서

1. **기획 확인**: 과목 문서(`subjects/<id>.md`)의 활동·별 기준·설정·음원·테스트를 읽고, ‘미결정’이나 모호한 점은 추측하지 말고 질문한다(정한 해석은 `planning-log.md`에 남긴다)
2. **화면 없는 로직부터**: 출제·판정·진도 같은 로직을 분리해 Vitest 테스트와 함께 만든다
3. **과목 모듈**: `src/apps/<id>/`에 `mount(el, ctx)` / `unmount()` 규약(03 문서 4-2)으로 화면을 만든다. 대사는 `voices.json`에 등록하고 개발 중에는 내장 음성으로 들으며 진행
4. **PC 확인 → 배포 → 실기기 확인**(아이패드 에어1 먼저, 갤럭시 항목은 점검표에 쌓아 둠)
5. **마무리**: 음원 목록 정리 → Typecast 제작 → 넣기 → 실기기 청취 (05 문서 15장) → 아래 체크리스트 → `main` 병합

작은 단위로 커밋하고 메시지는 한국어로 쓴다. 문서만 바꾼 커밋은 `docs:`.

## 2. 공통 규칙

- **별·스티커 공통 규칙** (껍데기가 처리, 03 문서 6장)
  - 별 기준은 과목이 정하되 “한 묶음(한 판·한 카테고리)을 끝내면 별 1개”를 기본으로 한다. 문제 하나마다 주지 않는다
  - 별은 과목별로 따로 쌓이고, 과목마다 교환 비율(3 / 5 / 10, 기본 3)에 도달하면 스티커 1장으로 자동 교환
  - **과목당 하루 스티커 1장.** 받은 뒤에는 그날 그 과목의 별·스티커 없음(연습은 계속 가능)
  - 과목은 `ctx.reward.star()`만 호출하고, 오늘 받았는지는 `ctx.reward.status().doneToday`로 확인한다
  - 별 기준은 각 과목 문서(`subjects/<id>.md`)에 적는다
- 문제마다 `ctx.log.record()`를 호출한다
- **두 기기 지원**: 모든 과목은 아이패드 에어1(Safari 12, 손가락·정전식 펜)과 갤럭시 탭 S6 Lite(Chrome, S펜)에서 동작해야 한다. 입력은 `ctx.input`만 쓰면 기기 차이가 감춰진다. 화면은 높이 기준으로 배치하고 가로 폭은 1024~1280 사이로 늘어날 수 있다고 보고 설계한다(02 문서 2-5, 10장). 과목 마무리 실기기 확인은 두 기기 모두에서 한다
- **가로 화면 고정**: 앱 전체가 가로 모드 전용이다. 과목 화면은 1024×684pt 영역 안에 스크롤 없이 들어가게 설계하고, 넘치면 옆으로 넘기는 페이지나 단계로 나눈다. 기본 배치는 ‘왼쪽 문제·그림 / 오른쪽 보기·버튼’. 예: 구슬 세기의 10칸 판은 5×2, 하루 순서 카드는 가로 한 줄, 그림 교실 캔버스는 가로형, 듣고 쓰기의 쓰기 칸은 가로로 나란히
- **음원**: 아이에게 들려주는 문장은 모두 과목의 `voices.json`에 대사 ID로 등록하고 `ctx.audio.say(id)`로 재생한다. 개발 중에는 내장 음성으로 대신 읽고, **과목 마무리 단계에서 음원 목록을 정리해(`docs/voice/<과목 id>/`) Typecast로 제작해 넣는다** — 05 문서 15장
- **과목 마무리 순서**: 기능 완성 → 실기기 확인 → 음원 목록 정리 → 음원 제작·넣기 → 실기기 청취 → `main` 병합
- **설정**: 과목 설정은 `settingsSchema`로만 정의한다(부모 모드에 과목별 설정 페이지가 자동 생성). 효과음·음성 읽기·소리 크기는 공통 설정이므로 과목에 두지 않는다. 각 과목의 ‘부모 설정’ 줄은 이 `settingsSchema` 항목 목록이다
- 지시문은 항상 음성으로(대사 ID 방식, 아래 ‘음원’)
- 효과음은 껍데기의 Web Audio 합성음(`ctx.audio.sfx`)을 쓰고 음원 파일을 늘리지 않는다
- 캔버스·획 판정은 2단계에서 `src/shared/canvas/`, `src/shared/judge/`로 분리해 `dictation`, `drawing`, `picture-math`가 함께 쓴다
- 과목마다 판정·데이터 로직은 Vitest 단위 테스트를 함께 만든다(한글쓰기 앱처럼 화면 없는 로직을 분리)
- 새 과목은 과목 문서(`subjects/<id>.md`)를 기준으로 만들고, 아래 ‘새 과목 추가 체크리스트’로 마무리한다

- **화면 문구**: 새 과목은 처음부터 strings를 쓴다(06 문서 4장 4). 과목 문구는 과목 폴더의 `strings.ts`, 껍데기 문구는 `src/core/strings.ts`
- **이용 권한**: 과목 안에 잠금 로직을 만들지 않는다. 부모의 ‘학습 범위’ 설정(예: 배운 한자)은 `settingsSchema`, 이용 권한은 `entitlements.ts` — 둘을 섞지 않는다
- **에디션**: 가족용 전용 과목은 06 문서 12장 ‘파일 위치’ 규칙대로 배치한다. 공개용 과목은 가족용 전용 폴더의 파일을 import·참조하지 않는다
- **기록**: 부모 기록에 쓸 정보(고른 답, 활동 종류 등)는 `ctx.log.record`의 `meta`에 남긴다. 과목별 기록 화면은 아직 없으며 나중에 공통으로 설계한다

## 3. 새 과목 추가 체크리스트

- [ ] `src/apps/<id>/index.ts`에 규약(4-2) 구현, 단위 테스트는 `tests/apps/<id>/`
- [ ] `registry.ts`에 한 줄 추가 (과목 id는 한 번 정하면 바꾸지 않는다)
- [ ] 아이에게 들려주는 문장은 모두 `voices.json`에 등록하고 `ctx.audio.say(id)`로 재생(개발 중에는 내장 음성으로 대신 읽힘)
- [ ] **마무리: 음원 목록 정리**(15장) → `docs/voice/<과목 id>/` 제작 자료 생성 → Typecast 제작 → `public/apps/<id>/voice/`에 넣기 → `npm run voice:check` 통과 → 실기기 청취
- [ ] 한 판 3~5분, 정답 시 `ctx.reward.star()`, 문제마다 `ctx.log.record()`
- [ ] `unmount()`에서 정리 확인(10번 열고 닫기 테스트)
- [ ] 호환성 검사 2종 통과(2-2)
- [ ] 가로 1024×684pt 과목 영역 안에 스크롤 없이 들어간다(10장). 세로 레이아웃은 만들지 않는다
- [ ] 아이패드 에어1과 갤럭시 탭 S6 Lite **두 기기에서** 실기기 확인(손가락·정전식 펜·S펜) 후 `main`에 병합 → 자동 배포
- [ ] 화면 문구는 strings를 썼다 (하드코딩 없음, 06 문서 4장 4)
- [ ] `localStorage`·`navigator.*` 직접 참조 없음, 외부 링크·네트워크 호출 없음 (기존 테스트 `safety`·`compat`·platform 참조 검사 통과)
- [ ] 가족용 전용 과목이면 06 문서 12장 ‘파일 위치’ 규칙대로 배치
- [ ] 과목 문서(`subjects/<id>.md`)에 구현하면서 바뀐 점을 반영하고, 결정 사항은 `planning-log.md`에 기록
- [ ] 갤럭시 탭 확인 항목을 `checklists/galaxy-tab-checklist.md`에 덧붙임 (갤럭시 확인 보류 중인 동안)
